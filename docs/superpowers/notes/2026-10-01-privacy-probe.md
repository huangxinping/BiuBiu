# 隐私权限实验结果（2026-10-01）

环境：macOS 27.0.1（26A434），实验程序 ad-hoc 签名，bundle id io.github.biubiu.tccprobe

第一次运行用 `open -W` 启动，第二次由用户在 Finder 中双击启动（确保访问只记在实验程序自己名下）。

| 目录 | 1 Spotlight 查询 | 2 文件属性 | 3 图标 | 4 书签 | 5 列目录（对照） | 6 读内容（对照） |
|---|---|---|---|---|---|---|
| 桌面 | OK；首次 3.1s（弹窗），再次 0.1s | OK 0.0s | OK 0.0s | OK 0.0s | OK 0.0s | OK 0.0s |
| 文稿 | OK；首次 1.8s（弹窗），再次 0.1s | OK 0.0s | OK 0.0s | OK 0.0s | OK 0.0s | OK 0.0s |
| 下载 | OK；首次 0.8s（弹窗），再次 0.1s | OK 0.0s | OK 0.0s | OK 0.0s | OK 0.0s | OK 0.0s |

第一次运行弹窗：3 次，分别请求访问"桌面""下载"和"文稿"，用户都点了"允许"。
第二次运行弹窗：无。

## 分析

- 弹窗出现在第 1 项：同一项在没有弹窗的第二次运行中只要 0.1 秒，第一次多出来的时间就是等待用户点击。第 5、6 项两次都是 0.0 秒，没有阻塞。
- 第 2–4 项都排在第 1 项之后，执行时已经获得授权，所以这次实验无法单独判断它们会不会触发弹窗。这不影响结论：BiuBiu 的界面会读取这些目录里文件的图标、检查文件是否存在、创建书签，第一次访问每个受保护目录时都会遇到同样的授权弹窗。
- 授权按 app 记录，点"允许"后一直有效。正式版用固定的自签名证书签名，升级后授权应当保持，任务 17 会实测这一点。
- 实验程序放在 `/private/tmp` 下，LaunchServices 没有登记它，`tccutil reset All io.github.biubiu.tccprobe` 两次都报 `No such bundle identifier`（OSStatus -10814）。系统里残留的授权记录只属于这个已删除的实验程序，不影响 BiuBiu。

## 结论

欢迎窗口取值：.expectPrompts

## 更正（2026-10-02）

上面的实验把 Spotlight 查询范围直接限定为每个受保护文件夹（`searchScopes = [文件夹]`），这样才会弹窗。BiuBiu 实际是在整个用户目录里查询（`NSMetadataQueryUserHomeScope`），这种查询**不会弹窗**，没有权限时只会悄悄去掉这三个文件夹里的结果。

用户在 v0.2.0 中打开了桌面上的一个文件，但面板里没有它。用 app 自己的身份查询（`open -n --stdout … --args --dump`）只有 126 条结果，桌面、文稿、下载的内容全部没有。从终端直接运行同一个程序（借用终端的权限）则有 2169 条。系统设置的"文件与文件夹"里也没有 BiuBiu。修复后，app 启动时先列出这三个文件夹的内容来触发授权，用户点"允许"后结果恢复为 2168 条。

开发过程中桌面文件"能显示"，是因为当时 app 是从终端直接启动的，借用了终端的权限。
